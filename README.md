# Wrecking Yard

A Unity WebGL build served from GitHub Pages as part of
[Little Joy Arcade](https://littlejoyarcade.site).

- **Play:** <https://jd4rider.github.io/wrecking-yard/play/>
- **Cover page:** <https://jd4rider.github.io/wrecking-yard/>

## What is in here

```text
build/WebGL/            the untouched Unity WebGL export (12 MB)
scripts/prepare-site.mjs  turns that export into a Pages-servable site
site/                   generated by the script, not committed
.github/workflows/pages.yml  prepare + deploy on every push to main
```

There is no bundler, no framework and no dependencies. The only build step is
`prepare-site.mjs`, which needs nothing but Node.

## Why there is a build step at all

Unity's default WebGL export Brotli-compresses the payload (`*.data.br`,
`*.wasm.br`, `*.framework.js.br`) and expects the web server to answer with
`Content-Encoding: br`. GitHub Pages serves files as-is and gives you no way to
set response headers, so the browser would hand raw Brotli bytes to the loader
and the game would fail before the first frame with a parse error.

`prepare-site.mjs` therefore:

1. copies the export to `site/play/`,
2. decompresses the three Brotli payloads and points `index.html` at the plain
   files (11.9 MB on disk becomes 55.5 MB over the wire — GitHub Pages gzips
   `.wasm` on the fly, but it is not the 8 MB a Brotli-aware host would send),
3. scales the template's fixed 900 × 1600 canvas to the window so the play area
   is never clipped on a laptop,
4. fails the build if any expected file is missing, so a broken export is caught
   in CI instead of in a player's console.

## Local development

```bash
node scripts/prepare-site.mjs
python3 -m http.server 8080 --directory site
# open http://localhost:8080/play/
```

Serve it over HTTP rather than opening the file — Unity's loader fetches the
payload and will not work from a `file://` URL.

## Updating the build

Re-export from Unity, then replace `build/WebGL/` with the new export and push:

```bash
rm -rf build/WebGL
cp -R "/path/to/Wrecking Yard/Builds/WebGL" build/WebGL
git add -A && git commit -m "Update the WebGL build" && git push
```

Keep the export's compression setting on Brotli or Disabled; both work. Gzip and
`.unityweb` payloads are not handled by the script and will fail the build with a
clear message.

To cut the download size properly, re-export with **Publishing Settings →
Compression Format → Disabled** (biggest files, no CPU cost) or
**Decompression Fallback** (Unity embeds its own Brotli decoder in the loader, so
the compressed files can be served unchanged at ~12 MB).
